新增 10 項主機測試涵蓋：四份實際動畫的邊界與影格、截斷／重複 action／無效色盤、四點校正與 180° 座標、手勢抬起／拖曳／長按／millis 回繞、照顧與模擬 NVS 重載、遊戲獎勵只發一次、訓練／放生確認、設定按鈕、十頁分塊繪圖與整張繪圖像素一致，以及 USB 時間溢位與非法輸入。

主機 NVS 是記憶體模擬器。其通過不等於板上 Flash 寫入或斷電保存已驗收。主機繪圖轉接器也不能證明 LCD 色序、真實字形邊界或更新速度。

機器可讀摘要、正規化建置紀錄與主機測試輸出位於 [`evidence/cyd/`](../../evidence/cyd/)。兩份套件的 `manifest.json` 保存精確來源 SHA-256；未宣稱不同電腦重編譯會得到逐位元相同的 app。

## 建置警告

- TFT_eSPI 顯示 `TOUCH_CS pin not defined`：本版另以 VSPI 驅動 XPT2046，刻意不使用 TFT_eSPI 的同匯流排觸控功能。
- 固定的 Arduino ESP32 2.0.14 有 `uartSetPins` 回傳值警告，來自既有框架；兩種環境均完成連結與映像產生。
- 本機 PlatformIO Python 環境有 urllib3 / LibreSSL 警告；下載與編譯已完成。

## 待實機驗收

此清單為初始計畫；已完成項目見下節，目前仍需真正斷電與長時間運行測試。

1. 確認 ESP32、4 MB、LCD 型號與 USB 資料連線；備份原 Flash。
2. 燒錄後讀取版本、`psram=0`、`band_bytes=15360`、heap 與最大可用區塊。
3. 確認 ST7789／ILI9341 色序、方向、四點校正與邊緣點擊；檢查 180° 後觸控。
4. 實際操作餵食、摸摸、睡眠／喚醒、清潔、兩種遊戲與取消放生。
5. 保存亮度與校正後重開機；真正斷電再開機，檢查角色與進度仍在。
6. USB 校時後驗證離線時間只套用一次；持續運行觀察 FPS、輸入延遲與 heap。

第一版沒有音效、完整 microSD 素材、Wi-Fi 校時、電池與低功耗功能；這些不是已驗收項目。

## 0.2.0 滿版像素介面與實機結果

- 依使用者核准的版面完成滿版像素場景、縮小角色、四個原生圖示、需求視窗與像素選單。首影格 76×100；角色、背景與大圖示同為 4×4 像素格。

- 兩個 ESP32 建置成功：ST7789 app **960,960 bytes**、ILI9341 app **961,056 bytes**；靜態 RAM 兩版皆 **23,044 bytes**。套件來源、映像 SHA-256、ESP32 chip ID、分割表與完整 factory 合併內容檢查通過；原微雪 core 與韌體未修改。
- 重新確認同一塊 CH340／ESP32-D0WD-V3／4 MB 板，重新核對原始完整 Flash 備份；只寫入 `0x10000` app，esptool 校驗成功。更新前後完整 **20,480 bytes NVS 逐位元相同**，角色與校正保留。裝置讀回 `0.2.0-cyd`、`calibrated=1`、`psram=0`。

## 0.3.0 節奏擊掌

- 依使用者預覽選擇移植「節奏擊掌」，加入遊戲選單第一項；原接星星與力量訓練仍可操作。沿用 Flash 原生動畫，新增抬手靠近、像素手掌、亮區提示、愛心、星星及早／晚／漏拍回饋，沒有新增音效。
- 每局 12 拍，每拍 1,500 ms，接受時間為該拍 930–1,380 ms；每拍只能計分一次。18 秒結束，記錄總成功次數與最高連擊，沿用原遊戲獎勵；提早返回不結算獎勵。遊戲期間延後週期性存檔，避免 Flash 寫入停頓影響節奏。
- 本輪完整 **178 項、27,804 assertions** 通過，同套 AddressSanitizer／UBSan 通過；USB 工具 6 項通過。新增測試涵蓋時間窗邊界、millis 回繞、連點、漏過多拍、連擊、12 拍結算只發獎一次、取消、舊遊戲入口，以及擊掌不同狀態的分塊／整張繪圖一致。
- 主機產生 20 張畫面；5 張新增示例涵蓋準備、等待、可擊掌、成功與結算。原核准主畫面仍為 76,800 像素全數一致。
- 兩種螢幕均編譯成功；最後 app 為 ST7789 **966,976 bytes**、ILI9341 **967,072 bytes**，靜態 RAM **23,060 bytes**，繪圖區塊仍為 **15,360 bytes**。套件 SHA-256、來源雜湊、分割表與合併映像通過檢查。
- 已重新確認同一塊 CH340／ESP32-D0WD-V3／4 MB，核對原完整 Flash 備份，最終只寫 app 並通過 esptool 校驗。更新前後 **20,480 bytes NVS 逐位元相同**。啟動讀回 `0.3.0-cyd`、`species=25`、`calibrated=1`、`psram=0`、heap **332,028 bytes**、最大連續區塊 **114,676 bytes**，USB 校時成功。
- 連續觀察 **96.089 秒**，主畫面 heap 固定 **332,028 bytes**，最慢完整繪圖 **62.421 ms**。本次 USB 觀察未出現擊掌頁或結算頁，故僅證明啟動與主畫面短時間穩定；已請使用者測試完整回合，手動遊戲驗收仍為 pending。
- 後續使用者回覆「**節奏擊掌 可以**」，更新為使用者實機確認通過；此回覆與上述未觀察到遊戲的 USB 紀錄分開保留。
- 實機詳細狀態與使用者測試範圍見 `evidence/cyd/hardware-0.3.0-2026-11-24.json` 與 `runtime-0.3.0.json`。本輪沒有重新拍攝 LCD 或擷取遊戲畫面；遊戲中不使用會暫停輸入的 `CAPTURE` 指令。真正斷電、長時間運行與 ILI9341 實機仍未測。

## 0.4.0 接星星與力量訓練優化

- 接星星新增準備畫面、下落軌跡、剩餘時間條、皮卡丘追逐／跳接、命中特效及連擊。目標有額外 28 像素觸控容錯，後半局逐漸加快；漏接中斷連擊但不會提早終止 20 秒回合。
- 力量訓練新增準備畫面、900 ms 自動蓄力、1／2／3 分力道、角色前進出拳、沙包晃動與裂痕、擊破及恢復。每拳至少間隔 400 ms，避免連點重複觸發；滿力出拳後三分可見。訓練積分仍透過原 core 結算實際力量增加，原 core 未修改。
- 三款遊戲進行中均延後週期性存檔。計時從 START 才開始，提早返回不發獎勵；結算只發一次獎勵。節奏擊掌邏輯與五張示例 PNG 均維持已驗收 0.3.0，逐檔位元比較一致。
- 本輪 **182 項、27,884 assertions** 全部通過，同套 AddressSanitizer／UBSan 通過；USB 工具 6 項通過。新增涵蓋下落座標／容錯、命中動畫防連點、蓄力級距、沙包擊破／恢復、時間回繞、準備／取消／結算，以及各動作的完整／分塊像素一致。
- 產生 28 張主機繪圖示例，原核准主畫面的 76,800 個像素依然全數一致。ST7789 app **970,192 bytes**、ILI9341 app **970,288 bytes**；靜態 RAM **23,132 bytes**。兩套建置、套件 SHA-256、來源、分割表及 factory 合併均通過。
- 已辨識同一塊 ESP32-D0WD-V3／4 MB、重新核對原備份，僅更新 app 並通過 esptool 校驗。更新前後 **20,480 bytes NVS 完全相同**。新版讀回 `0.4.0-cyd`、`calibrated=1`、`psram=0`，啟動後 heap **331,956 bytes**、最大連續區塊 **114,676 bytes**。
- 使用者實際試玩後回覆「**兩款的畫面與體驗都有改善**」。此項驗收是使用者對兩款畫面與操作體驗的確認；完整計分／獎勵路徑的機器測試另列，不將兩者混用。
- USB 共觀察 **128.487 秒**，包含兩款遊戲的實際操作；接星星取樣分數最高 5，訓練取樣積分最高 12。heap 全程固定 **331,956 bytes**，最慢完整繪圖 **66.106 ms**。未取樣到結算頁，故不把這份 USB 紀錄當成完整結算或獎勵的實機證據。
- 詳細狀態見 `evidence/cyd/hardware-0.4.0-2026-11-24.json` 與 `runtime-0.4.0.json`。本輪未重新驗證 ILI9341 實機、斷電、長時間運行或新 factory 完整安裝，也未推送或執行遠端 CI。
